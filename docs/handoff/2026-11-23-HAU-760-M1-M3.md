## Calls I made where the plan was silent or off

1. Dependency spec is `git+ssh://...#<tag>`, not `github:...#<tag>` (see the blocker above).
2. `app.plugin.js` is `require("./plugin/build").default` (the plugin is compiled from an ES default export).
3. `PushContext` (named, never defined) is `{ deviceId, app, schemaVersion }`; M5 may extend it.
4. `Transport` gained optional `signIn()` and `signOut()` for Android's consent and revoke; without them signing in
   means `account()` is available.
5. `installSync(db, config, { deviceId? })` and `CloudSyncProvider`'s `transport` prop exist so the example can run
   two databases in one process. Tests use `installSyncWith` and `createCloudSyncWith` (no React Native).
6. `src/create.ts` holds the React Native wiring (AppState, launch flag, default transport); the core files stay
   importable under bun. Without a platform transport (until M4 and M5) the sync reports `unavailable`.
7. Sync is enabled by default on both platforms. Android's "off until the user signs in" comes from the Drive
   transport's `account()` answering `none` (state `signedOut`); `enabled = '0'` is only the user's switch.
8. The `hold` is stored as `needsAppUpdate@<schemaVersion>` and clears itself once the app's schema version changes.
9. Pull pages and push results are written in `withExclusiveTransactionAsync`, so `applying = '1'` is never visible
   to the app's own writes on the main connection (they would otherwise go unrecorded).
10. A reset (expired token, zone gone) also clears `_sync_rows.sys`; conflicts re-learn the tags.
11. A push result `failed/other` ends the cycle in `error`. The 2 s write timer only starts a cycle from `idle` and not
    while a retry is scheduled, so a stopped state is never hammered.
12. Restore detection also fires on the very first `installSync` (no stored id): that marks existing rows dirty,
    which is the first sync an app adopting the module needs.

## Watch out for

- Triggers persist in the database file, so a later app migration on a synced table runs with them live: an UPDATE
  that keeps or lowers `updated_at` gets bumped by one and marked dirty. A seed migration (`updated_at = 0`) only works
  before the first `installSync`, which is the case for each app's adoption migration (A1, A2), not after.
- BLOB columns are not supported in payloads (JSON).
